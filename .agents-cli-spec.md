# Agent Spec

## Overview
Student Companion is a local Google ADK multi-agent prototype. It routes exam-planning requests to the existing Smart Study Planner workflow and routes other requests to a personal assistant that can search the web, calculate arithmetic, analyze text, or converse normally. The study planner continues to use sequential, parallel, and loop agents to produce and validate personalized day-wise plans.

## Example Use Cases
- Given a subject, preparation days, current level, syllabus topics, and available hours per day, produce a complete study plan covering exactly those days.
- If any required detail is missing, ask only for the missing information instead of inventing it or generating a partial plan.
- If a draft exceeds the daily time allowance or omits a topic, return specific corrections and revise the plan.
- Search for current information and return source links when the user explicitly asks for web research.
- Perform deterministic arithmetic and count characters, words, and sentences in supplied text.

## Tools Required
- Existing Gemini model configuration only.
- Google Search grounding, isolated inside the search specialist agent.
- Local deterministic calculator, text analyzer, and study-plan validation tools.
- No database or additional authentication is added.

## Constraints & Safety Rules
- Preserve the existing model name and environment configuration.
- Never invent missing subject, preparation days, current level, syllabus topics, or daily study hours.
- Cover every supplied topic.
- Never exceed the supplied daily study-hour limit.
- Use the requested number of preparation days; do not assume ten days.
- Include revision and a final mock test.
- Stop with an explicit validation failure if the iteration limit is reached without approval.
- Use web search only for requests that need current or external information.
- Use the calculator for arithmetic and the text analyzer for exact text counts.
- Never invent search or tool results.

## Success Criteria
- The workflow imports successfully and preserves its existing model configuration.
- Missing-input requests do not proceed as if a complete plan can be generated.
- No instruction contains a hard-coded ten-day requirement.
- Deterministic validation reports missing topics, incorrect day count, daily time-limit violations, and missing revision or mock-test coverage.
- Review feedback is separate from the final user-facing presentation.
- Study-planning requests route to the validated planner workflow.
- Current-information requests route to the isolated search specialist.
- Arithmetic and text-counting requests use their deterministic tools.
- General conversation does not accidentally start the study-planning workflow.

## Reference Samples
The official deep-search sample was studied for its isolated Google Search specialist pattern. This project reuses that boundary without copying the sample's research loop or frontend. The existing study-planner sequential, parallel, and loop-agent design is retained.
